# MuscleScope：面向实习与研究的项目战略

## 一句话场景

力量训练者仅凭体感很难稳定判断动作轨迹、左右差异及目标肌群负荷；现有单摄像头应用多停留在关键点和次数。本项目用可解释证据链输出姿态观测、肌骨模型估计和可选传感器测量，并明确置信度。

这是产品假设，不是已经验证的市场事实。后续要通过访谈和实验验证。

## 最终形态

### A. 传统后端能力

Java Spring Boot负责：

- 用户、动作库、训练计划、训练记录
- 视频分析任务及状态机
- PostgreSQL持久化
- Redis只在出现真实缓存/幂等需求后引入
- 对象存储保存视频，数据库只存元数据
- 权限、隐私删除、审计日志
- Python分析服务调用、超时、重试和幂等

这部分对应Java后端实习。

### B. AI/生物力学分析能力

Python负责：

- 视频解码、2D姿态、置信度
- 时序滤波、动作分段、计数
- 双机位标定与3D重建
- OpenSim个体化模型和肌肉激活/肌肉力估计
- 评测、失败样本与模型版本
- FastAPI仅作为服务边界，不把算法塞进路由

这部分形成项目差异化。

### C. 受控教练Agent

Agent只读取结构化分析结果、训练历史和动作知识，不直接凭视频编造结论。它可以：

- 解释本次动作问题
- 追问疼痛、器械重量、目标和RPE
- 调用训练记录、动作知识、计划生成等工具
- 在低置信度或疼痛场景停止建议并建议人工处理
- 输出引用、工具轨迹、延迟和成本

Agent必须有最大步数、超时、预算、工具参数校验、失败降级和评测集。

## 项目深度阶梯

### M0 基础（4周）

纯Python几何、文件、JSON、异常、测试、Git。不是简历项目，但确保你能读懂代码。

### M1 可演示（8—12周）

单机位深蹲：关键点、角度、状态机、计数、低置信度拒绝、30段测试视频。形成第一个可展示版本。

### M2 后端完整（4—6个月）

Java业务服务 + PostgreSQL + Python分析服务 + 任务状态 + Docker + 接口测试。完成真实部署和5—10位体验者反馈。

### M3 技术壁垒（6—12个月）

双机位3D、个体化尺度、OpenSim、外部负荷、肌肉力估计，和公开基线或实验室数据比较。

### M4 研究验证（12—24个月）

EMG/力板/动作捕捉对照，形成数据集、论文、竞赛或软著。

M1能写简历，M2是较强本科工程项目，M3以后形成明显辨识度。

## 什么手搓，什么复用

### 必须亲手实现并讲清

- 向量/角度、状态机、计数和基础滤波
- JSON校验、错误处理、领域对象
- Java业务层、数据库表和关键SQL
- 分析任务状态、幂等、超时与失败重试
- 评测脚本、数据划分、指标计算
- Agent工具schema、停止条件和评测
- 项目适配层及至少一个真实难点修复

### 应当复用

- MediaPipe/RTMPose等姿态模型
- OpenCV视频编解码
- OpenSim/Pose2Sim生物力学能力
- Spring Boot/FastAPI框架
- PostgreSQL驱动、认证和成熟基础组件

### 不应该现在手搓

- 深度学习框架、数据库、Web框架
- 通用向量数据库或消息队列
- 从零训练大型姿态模型
- 自研加密、认证协议

原则：业务与评测亲手做，通用基础设施复用；复用后必须能找到入口、画出调用链、修改适配器并解释许可证。

## 技术栈引入门槛

- PostgreSQL：训练记录和半结构化分析结果确实需要查询后引入。
- Redis：出现热点读取、幂等键或任务状态性能问题，并有前后数据后引入。
- 消息队列：视频任务耗时导致HTTP同步请求不可接受时引入。
- Elasticsearch：动作知识全文检索确有规模和搜索质量需求时引入。
- 向量库/RAG：教练回答需要从动作规范和用户记录检索证据时引入。
- 微服务：在Java与Python职责边界之外，不为了简历拆服务。

没有问题、基线和数据的技术栈，不构成亮点。

## 三个计划中的选型问题

1. 单机位还是双机位：比较部署成本、3D精度、失败率和用户操作复杂度。
2. MediaPipe还是RTMPose：比较设备速度、关键点误差、许可和部署体积。
3. 同步处理还是异步任务：比较短视频P95延迟、失败恢复和系统复杂度。

完成实验后才能写结论。
