# 教练情感回应Agent：保留接口、非关键路径

## 已选择场景

作为MuscleScope教练模块，理解健身用户话语中的显式情绪、隐含需求和风险信号，再结合真实动作分析结果生成回应。

例子：“这组还能继续，就是膝盖有一点怪。”系统不能只鼓励坚持，需要识别逞强与疼痛风险，停止自动加量并给出安全建议。

## 为什么暂不单独建仓库

- 当前主目标是2027暑期实习，基础、M1视频分析和M2后端优先级更高。
- 现在拆第二仓库会复制账号、接口、部署和评测基础设施。
- 它和训练历史、动作结果、安全规则天然属于同一产品。
- 等模块有独立数据集、接口和评测后，可以抽取为独立的CoachDialogue-Eval仓库；在此之前拆分只是包装。

## 完整产品不依赖Agent

定义统一接口：

```text
CoachResponder.respond(context) -> CoachReply
```

可有两个实现：

- TemplateCoachResponder：规则与审核模板，默认可靠方案。
- AgentCoachResponder：模型、工具调用和情感策略，后续可选。

Agent关闭、超时或评测不达标时自动使用模板。因此即使暑假前没完成Agent，MuscleScope仍是完整的动作分析与训练记录产品。

## Agent Lite最小范围（仅在M2达标后）

输入：

- 用户本轮文本
- 动作分析结构化结果和置信度
- 最近训练摘要
- 疼痛/RPE等用户确认信息

输出：

- 显式情绪标签
- 隐含需求标签
- 风险等级
- 采用的回应策略
- 最终回复
- 引用的数据字段

工具只保留动作知识查询、训练记录查询和建议生成。禁止多Agent、长期记忆平台和无目标RAG堆叠。

## 评测

先人工编写并双人复核约100条场景，覆盖挫败、焦虑、过度自信、疼痛隐瞒、普通咨询和输入不足。比较模板基线与Agent：

- 情绪/隐含需求标签F1
- 高风险召回率
- 回应策略符合率
- 是否忠于动作分析
- 工具调用成功率
- P95延迟与单次成本

没有评测数据时，不在简历声称“更懂情感”。

## 启动条件

同时满足后才能开发：

- M1可演示且指标可复现
- M2核心请求链可运行
- 算法/Java学习没有连续两周延期
- 每周仍能稳定投入至少4小时项目时间

否则保留接口和文档，延后到实习准备完成后。

## 独立项目判定

满足以下条件才拆为第二项目：

- 至少100条版本化评测数据
- 模板基线与Agent对比
- 独立API和自动测试
- 至少一个真实调用方
- 能独立部署
- 有两个可讲选型或失败修复

在此之前，它是MuscleScope可选模块，不单独占一条简历项目。
